# Ikkyee 앱 개발 계획 - 간단 버전

## 목표

- 웹의 주요 기능을 iPhone과 Android 앱으로 옮긴다.
- 휴대폰 사진 원본은 휴대폰에만 저장한다.
- 사용자가 직접 선택한 사진만 서버에 저장하거나 공개한다.
- 웹과 앱은 같은 계정과 공개 데이터를 사용한다.

## 저장 방식

| 데이터 | 저장 위치 |
| --- | --- |
| 휴대폰 사진 원본 | 휴대폰 사진 앱 |
| 사진 썸네일 | 휴대폰 임시 캐시 |
| 앱 내부 앨범 정보 | 휴대폰 SQLite |
| 공개하거나 클라우드 저장한 사진 | Supabase |
| 계정, 닉네임, 좋아요, 댓글 | Supabase |

## 개발 순서

### 1단계: 앱 기본 준비

- React Native와 Expo로 앱 프로젝트를 만든다.
- iPhone과 Android에서 사진 접근이 가능한지 확인한다.
- 사진 전체 접근, 선택 접근, 접근 거부 상태를 확인한다.
- 웹과 같은 Supabase 계정으로 로그인되게 연결한다.

### 2단계: 휴대폰 사진 기능

- 휴대폰 사진을 앱에서 목록으로 보여준다.
- 썸네일과 원본 사진을 볼 수 있게 한다.
- 사진의 촬영일과 위치를 읽는다.
- 사진 위치를 지도에 표시한다.
- 위치가 없는 사진은 직접 위치를 지정할 수 있게 한다.
- 앱 내부 여행 앨범을 만들고 사진을 정리한다.

### 3단계: 사진 변경 처리

- 앱을 다시 열면 새 사진과 삭제된 사진을 확인한다.
- 휴대폰에서 삭제한 사진은 앱 목록과 지도에서도 정리한다.
- 사진 접근 권한이 해제된 경우 삭제로 처리하지 않고 접근 제한으로 표시한다.
- 앱이 꺼져 있는 동안의 변경은 다음 실행 시 반영한다.

### 4단계: 웹 기능 연결

- 이메일, Google, Kakao, Apple 로그인을 지원한다.
- 프로필과 닉네임을 웹과 공유한다.
- 기존 클라우드 사진과 앨범을 앱에서도 관리한다.
- Explore 지도, 좋아요, 댓글, 공개 프로필, 공유 기능을 추가한다.
- 비밀번호 재설정 기능을 추가한다.

### 5단계: 클라우드 저장과 공개

- 사진은 자동으로 서버에 올리지 않는다.
- 사용자가 `클라우드에 저장` 또는 `공개`를 선택했을 때만 업로드한다.
- 공개 범위는 비공개, 링크 공개, 전체 공개를 지원한다.
- 업로드 중 앱이 종료되어도 다시 이어서 처리한다.
- 실패하거나 취소된 임시 파일은 자동으로 정리한다.

### 6단계: 안전 기능과 출시

- 계정 삭제 기능을 추가한다.
- 사진, 댓글, 프로필 신고 기능을 추가한다.
- 사용자 차단 기능을 추가한다.
- 대량 사진에서 속도와 메모리를 점검한다.
- 실제 iPhone과 Android 기기에서 전체 기능을 테스트한다.
- App Store와 Google Play 제출 자료를 준비한다.

## 삭제할 때의 동작

- 앱 앨범에서 제거: 앨범에서만 빠지고 휴대폰 원본은 유지한다.
- 휴대폰에서 삭제: 앱의 로컬 목록과 지도에서 빠진다.
- 이미 공개한 사진의 휴대폰 원본 삭제: 서버의 공개 사진은 유지한다.
- 클라우드 사진 삭제: 웹과 앱의 클라우드 목록에서 삭제하지만 휴대폰 원본은 유지한다.

## 지원 범위

- 지원: JPEG, PNG, WebP, HEIC, Live Photo의 대표 사진
- 첫 출시에서 제외: 동영상, RAW, 휴대폰 기본 사진 앱의 앨범 직접 수정

- Apple Developer 계정
- Google Play Console 계정
- Google, Kakao, Apple 로그인 앱 설정
- 테스트용 iPhone과 Android 기기
- 앱 이름, 아이콘, 개인정보처리방침 URL, 고객지원 URL

## 완료 기준

- 휴대폰 사진을 목록, 원본, 지도, 앨범에서 볼 수 있다.
- 휴대폰 사진 원본이 자동으로 서버에 올라가지 않는다.
- 선택한 사진만 웹과 앱에서 공유할 수 있다.
- 사진 삭제와 권한 변경 시 앱에 오류가 발생하지 않는다.
- 웹 계정과 공개 데이터가 앱에서도 동일하게 보인다.
- iPhone과 Android 실제 기기 테스트를 통과한다.
