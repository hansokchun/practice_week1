# Explore 발견 패널 초기 배포 기획

작성일: 2026-06-15

## 결정 요약

초기 배포에서는 사진 수와 사용자 수가 적다는 전제를 우선한다. Explore 지도에는 공개 사진의 핀을 모두 표시하고, `최신`, `좋아요`, `조회수` 같은 지도 카테고리는 아직 구현하지 않는다.

오른쪽에는 고정형 `발견` 패널을 추가한다. 이 패널은 현재 지도 시점 안에 있는 사진들을 섬네일로 세로 배치해, 사용자가 위아래로 훑어보며 보조 탐색할 수 있게 한다.

## 화면 구조

- 지도는 Explore의 메인 화면으로 유지한다.
- 데스크탑에서는 오른쪽에 고정형 `발견` 패널을 둔다.
- 패널은 확장하지 않는다.
- 패널은 전체 화면 사진 피드처럼 보이지 않게 하고, 지도 탐색을 보조하는 역할로 둔다.
- 모바일 패널 구조는 별도 결정 전까지 이번 범위에 포함하지 않는다.

## 지도 동작

- 현재는 공개 사진 전체 핀을 지도에 표시한다.
- 지도 카테고리 필터는 구현하지 않는다.
- 사진 수가 많아지는 이후 단계에서 `최신`, `좋아요`, `조회수` 카테고리 도입을 다시 검토한다.
- 섬네일을 클릭하면 해당 사진 위치의 핀을 지도에서 강조하고 기존 핀 프리뷰를 연다.
- 핀을 클릭하면 오른쪽 패널의 해당 섬네일도 선택 상태로 맞춘다.

## 발견 패널 동작

- 패널 이름은 `발견`으로 한다.
- 패널에는 현재 지도 화면 안에 있는 공개 사진만 표시한다.
- 사진은 세로 섬네일 리스트로 배치한다.
- 사용자는 패널을 위아래로 스크롤하며 사진을 훑어볼 수 있다.
- 사진을 클릭하면 지도에서 해당 위치를 확인할 수 있어야 한다.

## 사진 배치 기준

초기 버전에서는 복잡한 알고리즘을 사용하지 않는다. 단순하고 설명 가능한 규칙만 적용한다.

권장 기본 규칙:

1. 현재 지도 화면 안에 있는 공개 사진만 대상으로 한다.
2. 최신 사진을 기본적으로 우선한다.
3. 같은 업로더의 사진이 지나치게 연속 노출되지 않도록 가볍게 분산한다.
4. 인증된 사람의 사진은 약한 우선순위를 줄 수 있지만, 전부 앞에 몰아주지 않는다.
5. 일부 사진은 랜덤하게 섞어 신규 사진도 노출 기회를 갖게 한다.

이번 초기 버전에서는 좋아요, 조회수, 고급 랭킹, 유사 사진 자동 묶음은 구현하지 않는다.

## 조회와 좋아요 데이터

지도 카테고리는 아직 만들지 않지만, 이후 확장을 위해 사용자 반응 데이터는 쌓을 수 있게 설계한다.

- 단순 섬네일 노출만으로 조회수를 올리는 방식은 피한다.
- 프리뷰 열림, 사진 클릭, 일정 시간 이상 실제 화면 노출 같은 명확한 행동을 조회 기준 후보로 둔다.
- 좋아요와 조회수 기반 카테고리는 충분한 사진과 반응 데이터가 쌓인 뒤 도입한다.

## 대화에서 확정한 장기 방향

초기 배포 이후 사진 수와 사용자가 늘어나면, 지도와 발견 패널의 역할을 분리한다.

- 지도는 선별된 핀을 위치 맥락으로 탐색하는 공간으로 둔다.
- 발견 패널은 전체 공개 사진 풀의 노출 통로로 둔다.
- 사진이 많아진 뒤에도 `전체 핀` 카테고리를 지도에 별도로 추가하는 것은 기본 방향으로 삼지 않는다.
- 지도 카테고리를 도입한다면 `최신`, `좋아요`, `조회수` 정도의 단순한 카테고리부터 검토한다.
- 좋아요와 조회수 카테고리는 패널과 프리뷰에서 쌓인 반응 데이터가 충분할 때 의미가 있다.

## 발견 패널의 장기 역할

발견 패널은 모든 공개 사진을 한 번쯤 노출할 수 있는 보조 탐색 영역이다. 다만 사용자가 사진 피드 안으로 완전히 이동한 것처럼 느끼지 않게, 지도와 연결된 보조 패널로 유지한다.

- 기본 노출 범위는 현재 지도 화면 안의 사진이다.
- 패널에서 사진을 누르면 지도에서 해당 사진의 핀을 강조하고 프리뷰를 연다.
- 지도 핀을 누르면 패널의 해당 섬네일도 선택 상태로 맞춘다.
- 발견 패널은 전체 화면 패널이나 확장형 보드로 만들지 않는다.
- 사진이 많아져도 패널은 오른쪽 고정형 보조 탐색 영역을 유지한다.

## 피해야 할 패널 방식

다음 방식은 초기 또는 장기 방향에서 우선하지 않는다.

- 전체 사진을 화면 전체 그리드로 한 번에 보여주는 방식
- 사람 카드 목록을 먼저 보여주고 사람을 선택해야 사진을 볼 수 있는 방식
- 인기 유저나 인증 유저 사진을 무조건 먼저 몰아서 보여주는 방식
- 좋아요, 조회수, 유사도 기반의 복잡한 추천 알고리즘을 초기부터 적용하는 방식
- 같은 사람 또는 같은 장소의 비슷한 사진이 패널을 연속 점유하는 방식

## 사람, 인증, 신규 노출 기준

사람 기준 그룹핑과 인증 정보는 화면의 1차 탐색 단위가 아니라, 노출 품질을 조절하는 내부 기준으로 사용한다.

- 사용자는 먼저 사람보다 사진을 보고 고른다고 가정한다.
- 같은 업로더의 사진이 연속으로 너무 많이 나오지 않게 가볍게 분산한다.
- 인증된 사람의 사진은 약한 품질 가중치로만 사용한다.
- 인증된 사람의 사진을 전부 먼저 보여주는 구조는 만들지 않는다.
- 신규 또는 미노출 사진은 랜덤 섞기를 통해 노출 기회를 준다.
- 사진을 많이 올린 사람이나 누적 좋아요가 많은 사람만 계속 앞에 오는 구조는 피한다.

## 이후 추천 알고리즘을 붙일 때의 원칙

추천 로직은 필요해진 뒤에 단계적으로 추가한다. 초기 구현에서는 단순한 규칙으로 충분하다.

장기적으로 필요해질 수 있는 기준:

- 최신성
- 좋아요와 조회수 반응
- 신규 또는 미노출 여부
- 인증된 사람의 약한 가중치
- 같은 업로더의 반복 노출 제한
- 같은 장소와 시간대의 유사 사진 분산

이 기준들은 사용자에게 복잡하게 드러내지 않는다. 화면에서는 `발견`이라는 단순한 패널 이름과 사진 섬네일 탐색 경험을 유지한다.

## 이후 검토 기준

다음 조건 중 하나가 생기면 지도 카테고리와 선별 노출을 다시 검토한다.

- 현재 지도 화면 안의 공개 사진이 많아져 핀이 과밀해지는 경우
- 사용자가 핀을 잘 클릭하지 않는다는 행동 데이터가 확인되는 경우
- 좋아요와 조회수 데이터가 충분히 쌓여 랭킹이 의미를 갖는 경우
- 특정 업로더나 비슷한 사진이 발견 패널을 반복적으로 점유하는 경우

## 현재 원칙

초기 Explore는 비어 보이지 않는 것이 중요하다. 따라서 지금은 전체 공개 핀을 지도에 보여주고, 오른쪽 `발견` 패널로 사진을 보조 탐색하게 한다. 복잡한 추천 알고리즘보다 단순한 최신 중심 정렬과 가벼운 랜덤 섞기를 우선한다.
