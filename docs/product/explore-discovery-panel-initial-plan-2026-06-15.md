# Explore 발견 패널 초기 배포 기획

작성일: 2026-06-15

## 결정 요약

초기 배포에서는 사진 수와 사용자 수가 적다는 전제를 우선한다. Explore 지도에는 공개 사진의 핀을 모두 표시하고, `최신`, `좋아요`, `조회수` 같은 지도 카테고리는 아직 구현하지 않는다.

오른쪽에는 고정형 `발견` 패널을 추가한다. 이 패널은 현재 지도 시점 안에 있는 사진들을 섬네일로 세로 배치해, 사용자가 위아래로 훑어보며 보조 탐색할 수 있게 한다.

## 화면 구조

- 지도는 Explore의 메인 화면으로 유지한다.
- 데스크탑에서는 오른쪽에 고정형 `발견` 패널을 둔다.
- 패널은 확장하지 않는다.
- 패널은 전체 화면 사진 피드처럼 보이지 않게 하고, 지도 탐색을 보조하는 역할로 둔다.
- 모바일 패널 구조는 별도 결정 전까지 이번 범위에 포함하지 않는다.

## 지도 동작

- 현재는 공개 사진 전체 핀을 지도에 표시한다.
- 지도 카테고리 필터는 구현하지 않는다.
- 사진 수가 많아지는 이후 단계에서 `최신`, `좋아요`, `조회수` 카테고리 도입을 다시 검토한다.
- 섬네일을 클릭하면 해당 사진 위치의 핀을 지도에서 강조하고 기존 핀 프리뷰를 연다.
- 핀을 클릭하면 오른쪽 패널의 해당 섬네일도 선택 상태로 맞춘다.

## 발견 패널 동작

- 패널 이름은 `발견`으로 한다.
- 패널에는 현재 지도 화면 안에 있는 공개 사진만 표시한다.
- 사진은 세로 섬네일 리스트로 배치한다.
- 사용자는 패널을 위아래로 스크롤하며 사진을 훑어볼 수 있다.
- 사진을 클릭하면 지도에서 해당 위치를 확인할 수 있어야 한다.

## 사진 배치 기준

초기 버전에서는 복잡한 알고리즘을 사용하지 않는다. 단순하고 설명 가능한 규칙만 적용한다.

권장 기본 규칙:

1. 현재 지도 화면 안에 있는 공개 사진만 대상으로 한다.
2. 최신 사진을 기본적으로 우선한다.
3. 같은 업로더의 사진이 지나치게 연속 노출되지 않도록 가볍게 분산한다.
4. 인증된 사람의 사진은 약한 우선순위를 줄 수 있지만, 전부 앞에 몰아주지 않는다.
5. 일부 사진은 랜덤하게 섞어 신규 사진도 노출 기회를 갖게 한다.

이번 초기 버전에서는 좋아요, 조회수, 고급 랭킹, 유사 사진 자동 묶음은 구현하지 않는다.

## 조회와 좋아요 데이터

지도 카테고리는 아직 만들지 않지만, 이후 확장을 위해 사용자 반응 데이터는 쌓을 수 있게 설계한다.

- 단순 섬네일 노출만으로 조회수를 올리는 방식은 피한다.
- 프리뷰 열림, 사진 클릭, 일정 시간 이상 실제 화면 노출 같은 명확한 행동을 조회 기준 후보로 둔다.
- 좋아요와 조회수 기반 카테고리는 충분한 사진과 반응 데이터가 쌓인 뒤 도입한다.

## 이후 검토 기준

다음 조건 중 하나가 생기면 지도 카테고리와 선별 노출을 다시 검토한다.

- 현재 지도 화면 안의 공개 사진이 많아져 핀이 과밀해지는 경우
- 사용자가 핀을 잘 클릭하지 않는다는 행동 데이터가 확인되는 경우
- 좋아요와 조회수 데이터가 충분히 쌓여 랭킹이 의미를 갖는 경우
- 특정 업로더나 비슷한 사진이 발견 패널을 반복적으로 점유하는 경우

## 현재 원칙

초기 Explore는 비어 보이지 않는 것이 중요하다. 따라서 지금은 전체 공개 핀을 지도에 보여주고, 오른쪽 `발견` 패널로 사진을 보조 탐색하게 한다. 복잡한 추천 알고리즘보다 단순한 최신 중심 정렬과 가벼운 랜덤 섞기를 우선한다.
