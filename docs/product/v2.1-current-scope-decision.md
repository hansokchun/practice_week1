This document translates the v2.1 plan into decisions for the current codebase.
Use it as the working reference before changing frontend structure, database
schema, or visual design.

## Product Direction

The product is no longer a travel SNS first. The MVP promise is:

> Choose photos, and a travel map is created.

The app should prioritize a private map-based photo archive, then controlled
public sharing. Any feature that does not directly help users turn photos into
map-based travel records should be delayed.

## Keep From Current Project

### Keep As Core

- Supabase Auth, Database, and Storage integration in `auth.js`.
- Email/password and Google login flow.
- Photo upload flow with EXIF parsing.
- Manual location picker for photos without GPS.
- Canvas image compression into multiple display sizes.
- Leaflet map, Google map tiles, Google Places search, marker clustering.
- Photo marker rendering on the map.
- `photos`, `profiles`, `user_likes` baseline tables.
- Session restore and deep-link behavior, after adapting URLs.
- Vite build and Cloudflare Pages deployment.

### Keep But Refactor

- Current SPA modules in `js/` are worth keeping, but the screen model needs to
  change from one sidebar with panels into top-level sections:
  - Home
  - Myphoto
  - Explore
- Current `profile.js` album behavior is useful as a prototype, but album data
  should move away from `photos.album` text plus user metadata and toward real
  album/trip records.
- Current detail panel should become a modal or drawer, matching the v2.1 plan
  and the Stitch `Photo Detail Modal: Archival Archive View` screen.
- Current shared/community mode should become Explore, with map-first layout and
  public-photo sidebar.
- Current likes can stay, but only as a simple public interaction. Do not build
  ranking or recommendation around likes in MVP.

## Rebuild Or Replace

### IA And Navigation

Replace the current primary app mental model:

- Current: `My Stories` / `Community` toggle inside a map-sidebar layout.
- New: `Home` / `Myphoto` / `Explore` as top-level navigation.

Recommended routes or route-like states:

- `/`
- `/myphoto`
- `/myphoto/upload`
- `/myphoto/albums/new`
- `/myphoto/albums/:albumId`
- `/explore`
- `/profile/:handle`
- `/settings`

Because the app is currently a vanilla SPA, these can start as hash/history
states before adopting a full router.

### Myphoto

Myphoto becomes the product center. It should absorb the best current private
features while reducing clutter.

Build toward:

- Recent photos.
- Album list.
- Upload entry point.
- Album creation flow.
- Album detail with photo stream and sticky map.
- Photo detail modal.
- Delete handling.
- Private/public status indicators.

Use Stitch references:

- `My Photos Dashboard: Optimized Stream Layout`
- `Photo Upload: Myphoto Workspace`
- Upload screen before file selection.
- Upload complete screen.
- Album creation analysis/review screen.
- `Review Map: Unified Date Divider Style`

### Explore

Explore must be map-first.

Build toward:

- Full-screen public map.
- Public photo pins and clusters.
- Pin click opens right sidebar.
- Sidebar can open photo detail.
- Public album link.
- Public author profile link.
- Like action.
- Empty state when current map area has no results.

Use Stitch references:

- `Explore: Updated Detailed Map Background`
- `Explore: Selected Pin Sidebar View`

### Public Sharing And Privacy

The current `shared` boolean is too simple for v2.1. Keep it temporarily, but
replace it with a public review and visibility model.

New sharing must support:

- Photo-by-photo public/private review.
- Location precision:
  - `exact`
  - `approximate`
  - `hidden`
- Time precision or visibility.
- EXIF stripping for public display images.
- Clear revoke/unpublish behavior.

Use Stitch reference:

- Public settings screen.

### Data Model

Current model is enough for the prototype, but not enough for v2.1.

Keep:

- `photos`
- `profiles`
- `user_likes`

Add or migrate toward:

- `albums` or `trips`
- `album_days`
- `photo_groups`
- `public_settings`

Change `photos` over time:

- Current: `lat`, `lng`, `date`, `album`, `shared`.
- Target: original EXIF fields, final display location, geo source, album/trip
  relation, and public visibility fields.

## Defer Or Remove From MVP

### Defer Existing Features

- Comments: current code has comments, but v2.1 excludes comments from MVP.
  Hide or park this UI until after P2/P3.
- Community feed sorting by popular or best today. Explore should not become a
  ranking feed in MVP.
- Full profile demographic fields such as age and gender. They are not central
  to the core promise.
- Like-based popularity surfaces.
- Subscriptions and liked-items pages.
- Real-time notifications.
- AI recommendations or auto-generated trips.
- Native photo import helpers and external timeline integrations.

### Remove From Primary UX

- Social-network framing as the main product.
- Card-feed-first public discovery.
- Public comments in Explore.
- Any public sharing that exposes exact coordinates without review.

## Stitch Design Mapping

Use `Personal Travel Map Archive` as direction, not as literal drop-in code.

Adopt:

- Calm archival style.
- Map-first utility.
- Photo-rich cards.
- Public/private badges.
- Upload and review flow patterns.
- Public trip/profile presentation.

Do not blindly copy:

- Every long-form landing section.
- Decorative content that does not map to current data.
- Screens that assume backend entities not yet implemented.

Most relevant screens:

- `Home / Landing: Archival Archive Tool`
- `My Photos Dashboard: Optimized Stream Layout`
- `Photo Upload: Myphoto Workspace`
- `Explore: Updated Detailed Map Background`
- `Explore: Selected Pin Sidebar View`
- `Photo Detail Modal: Archival Archive View`
- `Public Trip: Jeju East Coast Drive`
- `Public Profile: Map View Tab`
- `Public Profile: Albums Tab`
- Public settings screen.

## Recommended Build Order

### P0: Align Product Shell

- Preserve current working upload/map/data behavior.
- Add Home / Myphoto / Explore navigation.
- Reframe current private feed as Myphoto.
- Reframe current shared feed as Explore.
- Convert detail panel direction to modal/drawer.

### P1: Myphoto And Album Core

- Build Myphoto dashboard from current photo/profile data.
- Add album/trip records or migration path.
- Build album detail with date-grouped photos and sticky map.
- Keep current upload pipeline, but place it inside Myphoto.

### P2: Public Sharing Safety

- Replace simple `shared` toggles with public review.
- Add location precision policy.
- Add public album and public profile views.

### P3: Polish And Later Social Features

- Reintroduce comments only if the product needs them.
- Add subscriptions, notifications, rankings, and AI features only after the
  map archive loop is strong.

## Immediate Decision

Do not rewrite everything from scratch. The current app already has valuable
infrastructure and working map/photo behavior.

The right move is a guided refactor:

1. Keep the data/upload/map core.
2. Replace the information architecture.
3. Adapt Stitch visual screens into the existing vanilla SPA.
4. Migrate database shape only where the v2.1 product needs it.
