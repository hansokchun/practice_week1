# Ikkyee 서비스 명세

## 제품 목표

Ikkyee는 여행 사진을 단순한 파일 목록이 아니라 시간과 장소가 연결된 개인 기록으로 보관하고, 사용자가 공개한 기록만 다른 사람에게 발견되도록 돕는다.

핵심 사용 흐름은 다음과 같다.

1. 이메일, Google 또는 Kakao로 계정을 만든다.
2. 사진을 올리면 촬영일과 위치를 읽고, 누락된 위치는 지도에서 지정한다.
3. 사진을 개인 보관함에서 정리하고 여행 앨범으로 묶는다.
4. 공개 범위를 선택해 사진 또는 앨범을 공유한다.
5. Explore에서 공개 사진을 장소 중심으로 발견하고 좋아요·댓글로 반응한다.

## 사용자와 화면

- 비회원: 전체 화면 랜딩, 공개 메인 콘텐츠, 지도 페이지의 공개 샘플과 공개 기록, 로그인·가입 진입
- 회원: 전체 화면 랜딩, 공개 사진 발견형 메인, 사진 업로드·관리, 좋아요 모음, 앨범 작성, 프로필 편집
- 랜딩: 최초 접속과 `#/landing`에서 관리자가 선택한 서버 공개 사진을 최대 12장까지 화면에 가득 채우고 10초마다 교차 전환한다. 서버 구성을 불러오기 전에는 샘플 사진을 노출하지 않고 중립 배경으로 대기한다. `여긴 어디지?`를 가장 크게, `이끼에서 당신만의 장소를 찾아보거나 공유하세요`를 보조 문구로 표시하며 중앙 버튼은 메인으로 이동한다. 하단에는 현재 사진의 위치를 `나라 · 큰 지역`까지만 위치 핀과 함께 표시하고, 누르면 해당 사진의 상세 화면을 연다. 상단에는 브랜드와 계정 메뉴만 사진 배경 위에 표시한다.
- 메인: 검색창 위에 `이끼에서 당신만의 장소를 찾아보세요`를 두고, 추천 검색어는 `도로`, `바다`, `사람`을 제공한다. 상단 지구 배경에는 위치핀 대신 로고를 닮은 잎 식물을 점선 경로로 연결한다. 아래에는 한 단어 제목의 `추천`, `시골`, `도로`, `바다`, `사람`, `도시` 공개 사진 가로 목록을 제공한다. 운영 배치는 AI 장면과 핵심 태그가 주제에 분명히 맞는 사진만 사용하고, 사진 하나를 여러 주제에 중복 배치하지 않는다.
- Home 검색은 공개 사진의 제목·장소·설명·앨범과 AI 태그·요약·장면·분위기를 검색한다. 여행 개념 동의어를 확장하되 정확한 단어 일치를 먼저 보여주고, 여러 단어 검색은 각 개념이 모두 있는 사진만 반환한다.
- 로그인 전후 메인: 로그인 상태와 무관하게 같은 공개 사진 발견 화면을 표시하며, 예전 개인 작업영역은 다시 표시하지 않는다. 서버 공개 사진이 하나라도 있으면 정적 샘플은 메인 검색과 주제 목록에 섞지 않는다.
- 메인 사진 섹션: 소제목은 왼쪽에 정렬하고 소제목·사진 사이는 데스크톱 20px·모바일 16px, 섹션 사이는 데스크톱 72px·모바일 44px의 세로 여백을 둔다. 각 주제에는 최대 8장의 미리보기만 두고 데스크톱에서는 약 5장이 한 번에 보이게 한다. 모바일은 화면 너비의 60%인 두 번째 사진을 중앙에 놓고 첫 번째·세 번째 사진이 화면 양끝에 걸쳐 보이게 한다. 실제 행이 표시된 뒤 최초 정렬하며 사용자가 넘긴 위치는 다시 초기화하지 않는다. 좌우 화살표는 목록 양끝에서 멈추며 추가 사진은 `전체보기`에서 확인한다. 공개 화면은 서버에 저장된 주제별 사진과 순서만 사용한다.
- 메인 지구 배경은 밝은 종이색을 포함하지 않는 투명 WebP를 사용한다. 기존 크기와 위치, 가장자리 마스크를 유지하고 곱하기 혼합 없이 페이지 배경 위에 표시해 브라우저의 강제 어두운 화면에서 별도 밝은 이미지 사각형이 남지 않도록 한다. 전체 배경을 한 장으로 합치지 않는다.
- 메인 사진 카드: 장소·설명 오버레이 없이 이미지만 표시하며, 실제 섹션 분류가 준비되기 전에는 현재 공개 사진으로 임시 채운다.
- 태그 전체보기: 지도 없이 사진 중심 갤러리로 제공한다. 서버에서 지정한 주제별 사진만 사용하고 주제 사이 사진 중복을 피한다. 관리자가 무작위 구성을 실행하거나 비어 있는 주제를 저장할 때 최대 20장을 한 번 선정해 순서와 함께 저장하며, 다음 관리자 편집 전까지 모든 접속에서 같은 구성을 유지한다. 상단에는 태그명과 지역 필터만 표시한다. 한 페이지에 30장을 표시하고 하단의 이전·다음 화살표 버튼을 직접 눌렀을 때만 이동한다. 페이지 전환 중에는 고정된 사진 칸을 먼저 보여 주어 이미지 로딩으로 레이아웃이 흔들리지 않게 한다.
- 헤더: 비회원은 `내 지도 만들기`와 로그인, 회원은 `사진 추가`와 계정 메뉴를 표시한다. 로고는 전체 화면 랜딩으로 연결한다.
- 지도 진입: 메인 검색 아래와 공개 사진 목록 끝에 `지도에서 둘러보기`를 제공하고 고정 하단 탐색은 두지 않는다.
- 계정 메뉴: `내 프로필`, `내 사진`, `좋아요한 사진`만 주요 항목으로 제공한다. 앨범은 `내 사진` 안에서 본다.
- Explore: 공개 사진의 지도·목록·상세·좋아요·댓글 화면
- Profile: 본인과 공개 사용자가 같은 구조를 공유하며, 본인에게만 편집 기능을 제공한다.

## 가입 전 사진 3장 체험 (2026-10-29)

- 별도 `체험하기` 버튼 없이 비회원 헤더의 `내 지도 만들기`로 사진 선택 창을 연다. 비회원이 메인에 들어올 때마다 버튼 옆에 코럴색 말풍선 `나만 아는 장소로 지도를 만들어보세요!`를 표시한다. 닫으면 현재 메인 방문 동안 숨기며 다른 페이지에서 메인으로 돌아오거나 새로 접속하면 다시 표시한다. 랜딩과 로그인 상태에서는 표시하지 않는다.
- 비회원도 로컬 사진을 최대 3장, 장당 15MB까지 선택해 사진·촬영일·위치를 확인한다. EXIF가 없으면 정보 없음으로 표시하며 위치는 지도 클릭·핀 이동 후 `이 위치로 지정`으로 적용하거나 `위치 없이 보관`을 선택한다.
- 지도는 `지도 열기`를 누를 때 기존 Google Maps 연동으로 불러오며 선택한 사진의 핀만 표시한다. 기존 지도 사용량 과금 정책은 그대로 적용된다.
- 사진 선택 창에는 `사진으로 내 지도를 만들어보세요`와 사진 고르기·사진 수·선택한 사진 정보·지도·저장 진행 버튼만 제공한다. 반복 가입·임시 저장 안내와 전체 비우기 버튼은 제거한다. 개별 사진 삭제는 유지한다.
- 가입 전에는 사진을 서버에 업로드하지 않는다. 원본과 지정한 위치는 같은 브라우저의 IndexedDB에 임시 보관하고 24시간 후 다음 접근 시 정리한다. 다른 브라우저·기기에는 초안이 이어지지 않는다.
- `내 보관함에 저장하기`는 비회원도 업로드 확인 화면으로 진행한다. 이 화면의 `업로드하기`를 누를 때 로그인 화면을 표시하며 회원가입으로 전환할 수 있다. 인증 후 선택한 사진만 복원해 자동 업로드하고 성공하면 본인 프로필 메인으로 이동한다. 이메일 가입은 메일 인증 후 로그인해야 저장한다. 사진 바이트와 좌표를 인증 복귀 메타데이터에 넣지 않고 사진 ID만 최대 3개 저장하며, 이 저장 의도도 최대 24시간 유효하다. 인증을 닫아 취소하면 자동 저장 의도를 지우고 사진 초안은 유지한다.
- 체험 사진은 계정의 자동 공개 설정과 관계없이 비공개로 저장한다. 수동 위치와 위치 없음 선택을 유지하고 저장에 성공한 체험 사진만 임시 보관에서 제거한다. 기존 회원의 일반 업로드 정책은 유지한다.
- 회원의 미저장 체험 초안은 계정별로 분리하고 다른 계정이나 비회원에게 표시하지 않는다. 가입 전 초안은 체험 저장을 위해 인증한 경우에만 해당 계정으로 옮기며, 기존 초안과 충돌하면 두 초안을 지우지 않고 안내한다.

## 계정 정책

- 이메일 가입은 확인 메일 인증 후 업로드와 공개 기능을 사용할 수 있다.
- Google과 Kakao 최초 로그인은 자동으로 계정을 생성한다.
- 신규 계정은 공통 기본 아바타와 이메일 앞부분 또는 `Guest` 이름으로 시작한다.
- 공급자 프로필 사진은 자동 적용하지 않는다.
- Kakao 로그인 후에는 이름과 사진의 미리보기를 보여주고 사용자가 적용 여부를 선택한다.
- 같은 Supabase 사용자에 연결된 여러 공급자는 사진·앨범·좋아요를 공유하고, 별도 사용자 ID는 데이터를 공유하지 않는다.

## 사진과 위치

- 허용 이미지 형식과 파일 크기는 업로드 전 검증한다.
- 브라우저에서 EXIF 촬영일과 GPS를 읽고 업로드 이미지를 최적화한다.
- 내 사진에서 선택한 사진은 일괄 공개·비공개 전환할 수 있다. 공개 전환은 신규 계정 제한을 확인하되 사진별 위치 정확도 선택을 변경하지 않는다.
- 내 사진은 등록 순, 촬영 최신순, 촬영 오래된 순으로 정렬한다. 등록 순은 최근 등록한 사진부터 표시한다. 전체 사진을 먼저 정렬한 뒤 16장씩 페이지로 나누고, 날짜가 없으면 뒤에 배치한다. 이전에 저장한 등록 오래된 순·좋아요 순은 등록 순으로 대체한다.
- 정렬을 바꾸면 첫 페이지로 돌아가되 선택한 사진은 유지한다. 같은 브라우저에서 계정별 정렬 기준을 기억하며, 서버의 사진 데이터와 공개 범위는 변경하지 않는다.
- 업로드가 끝나면 본인 프로필 메인으로 이동한다. 등록 사진 수와 본인 사진 지도를 표시하고 사진 탭에서 저장한 사진을 확인할 수 있다.
- 위치가 없는 사진은 전용 위치 지정 화면에서 목록을 순서대로 처리한다. 선택 사진을 크게 보며 장소 검색, 지도 클릭, 핀 드래그로 위치를 정한다. 핀을 정한 뒤에만 50m, 200m 순서로 가장 가까운 실외 360° 거리뷰를 선택적으로 확인하며, 거리뷰를 열거나 돌려도 저장할 핀과 지도 시점은 바뀌지 않는다.
- `정확한 위치`와 `대략 위치`는 사용자가 지정한 지점에 대한 확신 정도다. 어느 쪽을 선택해도 저장·공개 좌표는 바뀌지 않으며, EXIF 위치는 정확한 위치, 지도에서 수동 지정한 위치는 대략 위치를 기본값으로 사용한다.
- 사진 정보 수정에서는 위도·경도 입력칸을 노출하지 않고 지도 우측 상단에서 현재 핀 좌표를 실시간으로 표시한다. 공개 범위와 위치 정확도 설명은 각 제목 옆의 키보드 접근 가능한 도움말로 제공한다.
- 사진 상세의 점 3개 메뉴에서 사진을 다운로드할 수 있다. 저장된 좌표가 있으면 서버 원본을 바꾸지 않고 다운로드용 JPEG 복사본의 GPS EXIF에 해당 좌표를 기록하며, 좌표가 없으면 GPS EXIF를 추가하지 않는다.
- 선택 사진의 촬영 시간을 기준으로 위치가 있는 이전 2장과 이후 2장을 참고로 보여주고 그 위치를 재사용할 수 있다.
- 한국 전체 시점은 선택 전 지도 중심일 뿐이며, 사용자가 지도나 검색 결과에서 직접 위치를 고르기 전에는 핀이나 좌표를 저장하지 않는다.
- 사용자 설정은 `exact`, `approximate`만 제공한다. 좌표가 없으면 `위치 없음`이며 지도 핀을 만들지 않고, `hidden`은 이전 데이터 호환용으로만 취급한다.
- 비공개 원본 위치는 별도 위치 테이블과 RLS로 보호한다.
- 현재 사이트의 데모 사진과 샘플 계정 데이터는 삭제 가능한 테스트 자료이며 출시 보존 대상이 아니다.
- 사진 상세 거리뷰는 `exact` 위치에서만 정적 미리보기를 먼저 표시한다. 데스크톱에서는 미리보기에 마우스를 올리거나 키보드 초점을 맞추면 `스트리트뷰 보기`를 표시하고, 터치 화면에서는 버튼을 항상 표시한다. 사용자가 버튼을 누른 뒤에만 주변의 가장 가까운 실외 동적 파노라마를 생성한다.
- 정적 미리보기가 지원되지 않거나 불러오기에 실패해도 동적 거리뷰 버튼을 유지하고 안전한 안내 문구를 표시한다.
- 모바일 사진 상세는 닫기 버튼, 사진, 작성자와 사진 정보, 좋아요, 거리뷰 순서로 표시한다. 닫기 버튼은 안전 영역 아래 화면 상단에 유지한다.
- 사진 상세와 Explore 사진 패널은 정확한 위치에는 위도·경도를 표시하고, 대략 위치에는 좌표 대신 위치 아이콘과 `대략적인 위치`를 표시한다. 이 규칙은 사진 소유자와 다른 사용자에게 동일하다.
- 모바일 사진 상세의 좋아요 하트와 합계는 간격을 좁혀 날짜·위치와 같은 정보 구역 안에 표시한다.
- 사진 목록과 카드에는 960px JPEG 섬네일을 우선 사용하고, 상세 확대와 다운로드에는 원본을 사용한다. 새 업로드는 두 파일을 함께 저장하며 기존 사진은 소유자가 데스크톱에서 로그인했을 때 유휴 시간에 순차적으로 섬네일을 생성한다.

## 사진 AI 분석과 향후 여행사진 정리 서비스

- 새 사진을 저장하면 업로드 완료를 막지 않는 백그라운드 작업으로 Cloudflare Workers AI의 소형 비전 모델과 JSON 정리 모델을 순차 호출한다.
- AI에는 사진 파일만 전달하고 계정 정보, 좌표, 촬영일과 다른 사진 메타데이터는 보내지 않는다.
- 결과는 검색용 한국어 태그 최대 10개, 한 문장 요약, 장면 분류와 분위기 최대 3개로 제한한다. 인물 신원, 민감정보와 정확한 장소는 추측하지 않는다.
- 태그·요약·분위기에 외국어가 섞이면 한국어 항목만 정규화하고, 사용할 한국어 결과가 없으면 장면 분류를 기반으로 안전한 태그와 요약을 대체한다.
- 분석 API는 Supabase 세션과 사진 소유권을 확인하며, 완료된 사진은 재분석하지 않고 계정당 하루 최대 30장만 처리한다.
- 기존 사진 중 `pending` 상태인 본인 소유 사진은 로그인 후 순차적으로 분석하며, `failed`나 완료 사진은 자동 재시도하지 않는다.
- 사진 소유자는 사진 상세에서 AI 분석 상태, 요약과 태그를 확인할 수 있다. 다른 사람에게는 AI 분석 패널을 노출하지 않는다.
- 분석 실패는 업로드·사진 열람·공개 범위에 영향을 주지 않는다. AI 결과는 검색과 추천 보조 데이터이며 사용자가 작성한 설명을 덮어쓰지 않는다.
- AI가 사진을 골라 앨범을 자동 구성하는 기능은 추후 단계로 유지하며 현재 웹 화면과 계정 메뉴에는 비활성 진입점을 표시하지 않는다.
- 향후 앨범 구성 결과는 제안일 뿐이며 사용자가 제목, 설명, 사진 구성과 공개 범위를 확인하고 저장해야 한다.

## 공개와 소셜

- 사진과 앨범 공개 범위는 `private`, `link`, `public`을 사용한다.
- 설정에서 새 사진의 기본값을 `비공개 유지` 또는 `자동 공개`로 정할 수 있다. 이 값은 앞으로 올리는 사진에만 적용하고, 신규 계정 공개 한도를 넘는 사진은 비공개로 저장한다.
- 랜딩 관리자에서 첫 화면과 주제 사진 후보는 관리자가 좋아요한 공개 사진만 제공한다. 좋아요를 취소하거나 비공개가 된 사진은 다음 편집 초안에서 제외한다. 주제 사진의 무작위 선정은 관리자 편집 중에만 실행하고 결과를 서버에 저장하며, 원본 사진이 삭제되면 외래 키 연쇄 삭제로 주제 배정에서도 즉시 제거한다.
- Explore에는 공개 가능한 사진만 표시한다.
- 좋아요 상태와 합계는 `set_photo_like` RPC 한 트랜잭션에서 동기화한다.
- 좋아요 버튼은 사진 상세 맥락에서 하트 아이콘과 상태·합계로 표시한다.
- 사용자가 좋아요한 사진은 계정 메뉴의 `좋아요한 사진` 화면에서 확인한다.
- 내가 좋아요한 사진의 개수 알림은 제공하지 않는다. `received_like_inbox`는 다른 사람이 내 사진에 남긴 좋아요 이벤트만 집계하며, 알림을 누르면 확인한 시점까지 읽음 처리한다. 확인 중 새로 들어온 좋아요는 남기고, 새 이벤트가 오면 다시 알림을 표시한다.
- 사진 상세와 앨범 상세의 공유 아이콘은 카카오톡 공유 및 링크 복사 선택창을 연다. `/share/photo/:id`, `/share/album/:id`에서 공개 항목의 Open Graph 메타데이터와 실제 사진 썸네일을 제공한다. 비공개와 삭제된 항목은 차단하며, 공개 앨범의 썸네일에도 공개 멤버 사진만 사용한다.
- 댓글 작성·삭제 권한은 RLS와 작성자 식별로 제한한다.

## 앨범 만들기

- 앨범 이름은 선택 사항이다. 비워서 저장하거나 기존 이름을 지울 수 있다. 목록에서는 `제목 없는 앨범`으로 구분하고, 상세 화면에서는 제목의 빈 공간을 접는다. 이 표시 문구는 실제 제목으로 저장하지 않는다.

- 데스크톱은 왼쪽에 이름·설명·공개 여부를, 오른쪽에 날짜별 사진을 배치한다. 모바일은 같은 내용을 한 열로 제공한다.
- 사진 선택 화면을 왕복해도 입력한 이름과 설명을 유지하고, 선택 사진 수를 표시한다. 같은 날의 사진이 6장보다 많아도 모두 편집할 수 있다.
- 지도는 위치가 있는 사진을 담았을 때만 접힌 상태로 제공하고, 펼친 뒤에만 지도 API를 불러온다. 담은 사진들의 실제 좌표에 지도 마커를 연결해 이동·확대·축소를 따라가게 한다. 사진 구성이 바뀌면 전체 촬영 위치에 맞춰 시점을 잡고, 다시 펼치거나 썸네일만 갱신할 때는 사용자가 맞춘 시점을 유지한다. 위치 없는 사진에 장식 핀을 만들지 않는다.
- 저장 중 중복 클릭을 막고, 새 앨범의 사진 연결이 실패하면 불완전한 앨범을 제거하고 입력 초안을 유지한다.
- 공개 앨범 저장은 사진 자체의 공개 범위를 자동 변경하지 않는다.
- 이용자 공지 문안과 공유 절차는 [이용자 공유 가이드](user-sharing-guide.md)를 사용한다.

### 추후 기획: 일반형 / 여행기록형 선택 (2026-10-15)

**상태: 아이디어 저장, 구현 보류.** 현재 화면·기능·데이터 구조는 변경하지 않는다. 출시 필수 작업이 아닌 추후 기능이며, 재개 요청 전에는 구현하지 않는다.

확정된 요청:

- 앨범 생성 시 `일반형`과 `여행기록형` 중 선택할 수 있게 한다. 일반형은 현재 앨범과 동일한 구성으로 유지한다.
- 여행기록형은 처음에 여행 전체를 소개하는 메인 화면을 둔다. 메인 제목과 앨범 관련 정보를 배치하고, 모든 사진의 위치 핀이 보이는 큰 지도를 중심으로 구성한다.
- 메인 지도는 매우 간단한 표현으로 제공한다. 위치가 있는 사진의 핀 전체가 여유 있게 보이는 시점을 자동으로 잡고, 클릭·드래그·확대·축소 등 사용자의 조작으로 시점이나 선택 상태가 바뀌지 않게 한다.
- 위치가 없는 사진에는 임의의 핀을 만들지 않는다. 열람 권한에 따라 볼 수 있는 사진과 위치만 지도에 포함한다.
- 메인 화면 아래에는 현재 일반형과 같은 사진·기록 앨범을 이어서 표시한다.

추후 검토할 정보 후보(아직 확정하지 않음): 여행 기간, 국가·지역, 소개글, 대표 사진, 사진 수와 방문 장소 수. 제목 미입력 허용 여부 등 기존 정책과의 관계도 구현 재개 시 정한다.

미정 사항:

- 사용자의 마지막 설명인 `스크롤을 내리면 옆에 지도에...`는 미완성이므로, 본문 스크롤에 따른 옆 지도 핀 강조·시점 이동·고정 동작은 추측해서 확정하지 않는다.
- 메인 지도와 본문 옆 지도의 역할 구분, 모바일 배치, 일반형과 여행기록형 간 전환, 오프라인 다운로드 반영 범위는 구현 재개 시 정한다.

## 메인 지역 검색 (2026-10-17)

- 메인 검색창에서 나라·지역·도시를 입력하고 검색 버튼 또는 Enter를 누르면
  Google Geocoding으로 해당 장소의 지도 범위를 한 번 조회한다.
- 이미 불러온 실제 공개 사진의 좌표로 결과를 추리고 24장씩 표시한다.
  비공개·링크 공개·데모 사진은 제외하며, 위치 없는 사진은 사진 글 검색에서만 찾는다.
- 지도 범위는 행정구역의 정확한 경계가 아닌 사각형이므로 경계 근처 장소도
  포함될 수 있음을 결과에 알린다.
- 입력 중이나 페이지 이동 시에는 지역 조회를 하지 않는다. 도로·바다·사람 등
  기존 주제 검색은 로컬에서 처리하고, 지역 조회 실패 시 사진 글 검색으로 이어진다.
- 중복 제출·오래된 응답을 막고 조회 제한시간은 10초로 둔다. Google 장소 정보는
  현재 페이지 메모리에만 유지하며 영구 저장하지 않는다.

### 추가 유료 API 없는 검색 개선 (2026-10-18)

- `제주 바다`, `서울 야경`처럼 뒤에 붙인 주제어를 분리한다. 지역만 한 번 조회하고,
  해당 범위의 사진 설명·태그·기존 AI 메타데이터를 로컬에서 함께 검색한다.
- 같은 지역에서 주제만 바꾸면 현재 검색에 남아 있는 지도 범위를 재사용한다.
  Google 결과를 DB나 브라우저 저장소에 캐시하지 않으며, 새 지도도 생성하지 않는다.
- 단독 주제어는 지역 API를 호출하지 않는다. `올림픽 공원`, `Central Park`처럼
  지명으로도 쓰이는 접미사는 분리하지 않는다. `서울 #공원`, `제주 #숲`처럼
  주제에 `#`을 붙이면 의도한 지역·주제 조합으로 검색한다.
- 한글 띄어쓰기 차이, 대소문자, 전각 문자·유니코드 표현 차이를 정규화한다.
  모든 검색어를 만족하는 사진만 표시하고 직접 일치 결과를 동의어보다 우선한다.
- 검색 범위에 지역과 주제를 함께 표시한다. 주제에 맞는 사진이 없는 경우를 안내하고,
  지역 조회 실패 시에는 전체 입력어로 사진 글 검색을 유지한다.
- 이 개선으로 자동완성·주변 장소·AI 분석 API를 추가하지 않는다. 기존 지역 조회와
  이미지 전송의 사용량 요금은 기존 정책을 따른다.

## 사진 등록 참여 안내 (2026-10-23)

- 태그 사이 등록 안내는 흰색 바탕과 얇은 청록 테두리, 작은 도입 문구, 제목·설명·등록 버튼 순서로 구성한다. 데스크톱에는 사진 카드와 점선 경로를 표현한 가벼운 SVG 그림을 두고, 작은 모바일 화면에서는 그림을 숨기고 버튼을 전체 너비로 표시한다.
- 랜딩 진입 버튼과 태그 사이 등록 버튼은 같은 점선·핀·잎 그리기 효과를 공유한다. 마우스 호버와 키보드 포커스를 유지하는 동안 4초 주기로 반복한다. 첫 1.35초에 그린 뒤 완성된 로고를 잠시 보여주고 부드럽게 지운다. 터치 겸용 PC에 연결한 마우스도 지원하며, 모션 줄이기 설정과 평상시에는 완성된 로고를 정적으로 유지한다. 애니메이션은 페이지 이동이나 업로드 진입을 지연하지 않는다.
- 로그인한 회원의 본인 사진을 성공적으로 불러온 뒤 0장이면 메인에 첫 사진 등록 안내를 표시한다. 로딩·조회 실패·비회원에게는 이 안내를 표시하지 않는다. 닫기는 브라우저의 계정별 설정으로 저장한다.
- 메인에서 사진이 있는 주제 섹션 사이에 사진 올리기 카드를 한 번 표시한다. 3개 이상이면 두 번째 섹션 뒤, 2개이면 첫 섹션 뒤에 배치하고 검색 결과에는 넣지 않는다. 비회원은 기존 로그인 후 업로드 이동을 사용한다.
- 업로드 완료 시 첫 업로드를 구분해 축하하고 실제 저장 수·공개 범위를 안내한다. 방금 저장한 사진에 위치가 있으면 본인 프로필 지도로 이동하는 버튼을 제공하고, 위치가 없는 사진은 기존 위치 지정 흐름으로 이어진다.
- 안내에 신규 외부 서비스·유료 API·이미지 요청을 추가하지 않는다. 실제 사진 업로드·지도 열기의 기존 사용량은 기존 정책을 따른다.

## 데이터와 보안

- 브라우저에는 Supabase publishable/anon 키만 사용한다.
- 서비스 역할 키, OAuth 비밀 키, Cloudflare 토큰은 저장소와 브라우저 번들에 넣지 않는다.
- 공개 스키마 테이블은 RLS를 사용하고, 권한 상승 함수는 호출 역할과 대상 행을 함수 내부에서 검증한다.
- 사진 Storage 경로는 사용자 ID 기준으로 소유권을 구분한다.
- DB 마이그레이션은 `supabase/migrations`에 추가하고 적용 후 보안 advisor를 확인한다.

## 관리자 운영 화면 (2026-10-12)

- 메인의 관리자 진입 문구는 `관리자페이지`. 메인 구성, 계정 관리, 피드백을 별도 화면으로 제공한다.
- 계정 관리는 25개씩 조회하고 닉네임/이메일 검색, 정상/차단 필터를 지원한다. 최근 로그인은 Auth의 마지막 로그인 기록이며 실시간 접속 상태가 아니다.
- 계정을 선택하면 가입일, 로그인 방식, 이메일 인증, 소개, 사진/공개 사진/앨범 수와 최근 사진 최대 12장(48px 썸네일), 최근 처리 이력 20개를 표시한다.
- 관리자만 비공개 사진의 작은 파생 이미지를 5분 서명 URL로 조회할 수 있다. 원본, 비밀번호, 토큰은 계정 관리 응답에 포함하지 않는다.
- 경고/차단/해제는 5~500자 사유와 확인이 필요하다. 차단은 1일/7일/30일/장기로 로그인과 계정 활동을 제한하고 사진은 삭제하지 않는다. 관리자 본인과 다른 관리자는 제재할 수 없다.
- 경고는 사용자 알림에서 확인하며 확인 상태를 서버에 저장한다. 모든 조치는 요청 UUID로 중복 방지하고 처리 중/완료/확인 필요 상태를 이력에 남긴다.
- 서버의 최신 관리자 권한을 확인하는 `admin-accounts` Edge Function만 계정 디렉터리를 호출한다. 차단은 기존 JWT의 DB/Storage 접근에도 적용한다.
- 피드백은 별도 화면에서 25개씩 조회하고 유형/처리 상태 필터와 상태 변경을 제공한다. 조회/변경 권한은 서버 RLS로 검증한다.

검증: 자동 테스트 963개와 빌드 통과. 390px 모바일 및 데스크톱 브라우저에서 테스트 데이터로 검색/페이지 이동/작은 썸네일/경고 확인/제재 이력/피드백 필터를 확인했다. 서버는 롤백 트랜잭션으로 차단 계정의 RLS, 쓰기, 경고 확인, 해제 복구를 확인했고 익명 Edge 요청은 401로 거절한다. 실제 이용자에게 테스트 경고나 차단을 적용하지 않는다. 이미 발급된 이미지 주소와 브라우저 캐시는 만료 전까지 남을 수 있다.

성능 예산 검사는 기존 JS/CSS 초과를 포함해 아직 미통과(JS Brotli 77.89KB/70.5KB, CSS 31.39KB/30KB). 이미지 예산은 통과하며 예산 수치를 임의로 높이지 않는다. 보안 Advisor의 기존 두 공개 SECURITY DEFINER RPC 경고는 [해당 점검 안내](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)에 따른다. 새 관리자 디렉터리는 서비스 역할에만 실행 권한이 있다.

## 품질 기준

- 동작 변경은 먼저 `node:test` 계약을 추가하거나 갱신한다.
- 완료 전 `npm test`, `npm run build`, `npm run perf:budget`을 통과한다.
- 로그인, OAuth, 업로드, 지도, 공개 범위는 실제 모바일 기기 최종 QA 대상으로 유지한다.
- 모달은 열릴 때 내부로 초점을 이동하고, Tab 순환·Escape 닫기·초점 복귀를 지원한다.
- 데스크톱과 모바일에서 텍스트·이미지·패널이 뷰포트를 벗어나지 않아야 한다.

## 배포 기준

- 개발 브랜치: `dev`, Cloudflare Pages 개발 배포
- 운영 브랜치: `main`, Cloudflare Pages 운영 배포
- 검증된 `dev`만 `main`으로 승격한다.
- Supabase는 현재 단일 프로젝트를 공유하므로 호환 가능한 마이그레이션을 먼저 적용한다.
- 유료 플랜 전용 기능과 leaked-password protection은 출시 후 계획으로 분리한다.
