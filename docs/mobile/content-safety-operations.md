# 모바일 콘텐츠 신고·차단 운영 절차

**적용 범위:** Ikkyee 모바일 공개 사진 신고와 사용자 차단  
**시행 기준:** 2026-08-24  
**출시 관문:** 실제 담당자와 비공개 운영 기록 저장소를 지정하기 전에는 운영 배포 완료로 간주하지 않는다.

## 역할과 접근 경계

- 신고 운영 책임자는 매일 `content_reports`의 `pending` 항목을 확인하고 처리 기한을 관리한다.
- 1차 검토자는 신고된 공개 사진과 사유를 확인하고 `reviewing`으로 변경한다. 최종 조치자는 숨김·삭제·계정 조치와 `actioned` 또는 `dismissed` 결정을 승인한다.
- 운영 조회와 상태 변경은 Supabase Dashboard SQL Editor 또는 별도의 서버 측 운영 도구에서만 수행한다. 관리자 자격 증명은 모바일 앱, 로그, 이 저장소에 넣지 않는다.
- 모바일 클라이언트는 본인이 제출한 신고의 상태만 읽고 새 신고만 작성한다. 신고 수정·삭제와 다른 신고자 행 조회 권한은 없다.
- 신고자의 식별 정보와 추가 설명은 신고 대상 사용자에게 공개하지 않는다. 공개 답변·지원 답변에도 신고자를 추정할 수 있는 내용을 넣지 않는다.

## 우선순위와 최초 대응 시간

| 우선순위 | 예시 | 최초 대응 |
| --- | --- | --- |
| 긴급 | 즉각적인 신체 위험, 아동 안전, 명백한 개인정보·정확 위치 노출 | 발견 또는 접수 후 1시간 이내 |
| 높음 | 반복 괴롭힘·혐오, 비동의 민감 이미지, 구체적인 위협 | 24시간 이내 |
| 일반 | 스팸·광고, 저작권, 기타 정책 위반 | 72시간 이내 |

법적 판단이나 긴급기관 연락이 필요한 사안은 임의로 결론 내리지 않고 출시 책임자와 법률·안전 담당자에게 즉시 상향한다.

## 상태 흐름

`pending` → `reviewing` → `actioned` 또는 `dismissed`

1. `pending`: 새 신고다. 중복 신고를 합치더라도 원본 행은 삭제하지 않는다.
2. `reviewing`: 담당자가 대상, 사유, 반복성, 현재 공개 여부를 확인 중이다.
3. `actioned`: 콘텐츠 비공개·삭제, 경고, 계정 제한 등 승인된 조치를 완료했다.
4. `dismissed`: 정책 위반이 아니거나 증거가 부족하다. 무혐의와 증거 부족을 운영 기록에서 구분한다.

최종 상태를 기록할 때 `reviewed_at = now()`를 함께 설정한다. 클라이언트가 `status`, `created_at`, `reviewed_at`을 임의로 쓰게 하지 않는다.

## 검토 순서

1. 신고 ID, 생성 시각, 사유, 대상 사용자와 사진 ID를 확인한다.
2. 신고된 사진이 이미 삭제·비공개인지 확인한다. 삭제되었더라도 신고 행과 필요한 증거 보존 기록은 유지한다.
3. 같은 대상의 최근 신고 수와 동일 유형 반복 여부를 확인하되, 신고 수만으로 위반을 확정하지 않는다.
4. 정확한 위치, 이메일, 토큰, 원본 사진 주소 등 불필요한 개인정보를 운영 기록에 복사하지 않는다.
5. 정책 위반 범위에 비례한 최소 조치를 선택하고 다른 검토자가 최종 결정을 확인한다.
6. 상태와 `reviewed_at`, 조치 종류, 결정 근거, 검토자, 증거 보존 기한을 접근 제한 운영 기록에 남긴다.

## 조치와 롤백

- 콘텐츠 조치는 우선 공개 범위를 비공개로 전환해 추가 노출을 멈춘 뒤, 삭제 필요성을 별도로 판단한다.
- 계정 제한이나 삭제는 단일 신고만으로 자동 실행하지 않는다. 긴급 위험을 제외하면 반복성, 증거, 이의 제기 가능성을 확인한다.
- 오판이 확인되면 사진 공개 범위와 계정 상태를 이전 값으로 롤백하고, 신고 상태와 운영 기록에 정정 사유를 남긴다.
- DB 변경 전 대상 ID와 현재 상태를 기록하며 광범위한 일괄 수정이나 재귀 삭제 명령을 사용하지 않는다.

## 이의 제기와 사용자 안내

- 조치를 받은 사용자가 이의 제기를 제출할 수 있는 지원 채널을 출시 전에 공개한다.
- 이의 제기는 최초 결정자가 아닌 다른 검토자가 증거와 정책을 다시 확인한다.
- 신고자에게는 접수 사실만 알리고 대상에 대한 구체적 제재 내용이나 개인정보를 제공하지 않는다.
- 신고 대상에게는 적용 정책, 영향을 받은 콘텐츠, 이의 제기 방법을 안내하되 신고자 정보는 공개하지 않는다.

## 교대·장애 처리

- 처리 기한이 임박한 `pending`·`reviewing` 항목은 다음 담당자에게 신고 ID와 우선순위만 전달한다.
- 운영 도구나 Supabase 장애 중에는 긴급 신고의 접수 시각을 별도 접근 제한 기록에 남기고 복구 후 원장과 대조한다.
- 잘못된 RLS, 대량 노출, 관리자 자격 증명 노출이 의심되면 일반 신고 처리를 중단하고 모바일 장애 대응 절차의 개인정보 사고로 상향한다.

## 출시 전 남은 외부 지정

- 신고 운영 책임자와 대체 담당자
- 감시되는 공개 지원·이의 제기 이메일
- 접근 제한 운영 기록 시스템과 보존 기간
- 모바일 개인정보 안내와 커뮤니티 정책의 최종 승인본

이 네 항목은 사용자의 조직 결정과 외부 계정 설정이 필요하므로 지정 전까지 스토어 출시 관문은 열린 상태로 유지한다.
