# 모바일 화면 상태·접근성 감사

기준일: 2026-08-26

이 문서는 앱 소스와 자동 테스트로 확인한 범위와 실기기 출시 관문을 구분한다. 자동 검사 통과만으로 VoiceOver·TalkBack 또는 실제 화면 품질을 완료로 간주하지 않는다.

## 자동 접근성 근거

- `mobile/__tests__/accessibility-contract.test.ts`가 `app/`과 `src/`의 모든 `Pressable`을 TypeScript AST로 읽고 명시적 `accessibilityRole` 누락을 실패시킨다.
- 작은 아이콘 버튼과 지도 마커는 최소 44×44pt를 계약으로 고정한다.
- 본문에 쓰는 핵심 전경·배경 색 조합은 WCAG AA 일반 텍스트 기준 4.5:1 이상을 계산해 검증한다.
- 상태 변경과 오류 문구는 `accessibilityLiveRegion="polite"`를 사용하며 원시 인증·데이터베이스·네트워크 상세를 읽지 않는다.
- 앱 소스에는 의도적인 화면 애니메이션이 없어 현재 감속 모션 대체 경로가 필요하지 않다. 향후 애니메이션 도입 시 운영체제 모션 감소 설정을 별도로 따라야 한다.
- `mobile/app.json`은 출시 회전 정책을 `portrait`로 고정하며, 360px·390px 폭에서 입력 영역을 확보하는 좌우 여백을 계약 테스트로 검증한다.
- 로그인·비밀번호 변경·프로필·댓글 입력은 공통 키보드 회피 스크롤을 사용한다. iOS는 키보드 인셋·대화형 닫기, Android는 높이 회피·드래그 닫기를 계약으로 고정했다.

## 실기기 출시 관문

- iPhone VoiceOver와 Android TalkBack으로 화면 제목 → 본문 → 기본 동작 → 보조 동작 순서를 확인한다.
- 포커스가 숨겨진 화면·삭제 확인 뒤 배경·이미 닫힌 모달에 남지 않는지 확인한다.
- 시스템 글자 크기 최댓값에서 360px·390px 너비, 키보드, 안전 영역, 가로·세로 정책과 버튼 잘림을 확인한다.
- 실제 렌더링·이미지 위 텍스트·선택·비활성 상태 대비를 Accessibility Inspector와 Android Accessibility Scanner로 확인한다.
- 스위치 제어·외부 키보드에서 모든 주요 동작이 도달 가능하고 순환 함정이 없는지 확인한다.

이 실기기 관문이 끝나기 전에는 체크리스트의 전체 접근성 항목을 완료로 전환하지 않는다.
