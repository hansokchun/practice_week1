# 웹·앱 활동 연동 검수

기준일: 2026-09-07

## 결론

웹과 앱은 운영 Supabase 프로젝트 `pqczcponriukilrtpbdl`의 같은 Auth 계정과 서버 행을 사용한다. 서버에 저장되는 프로필, 게시 사진, 좋아요, 댓글과 사진 수정은 양쪽에서 다시 조회하면 동일하게 반영된다. 기기 사진 원본, 업로드 전 위치, 썸네일과 게시 재시도 작업은 앱 로컬 전용이며 사용자가 게시를 확정하기 전에는 웹과 동기화하지 않는다.

## 기능별 결과

| 활동 | 연동 상태 | 공통 저장소·동작 |
| --- | --- | --- |
| 이메일·Google·Kakao 로그인 | 연동 | 같은 Supabase Auth 사용자 ID를 기준으로 세션과 프로필을 공유 |
| 프로필 이름·소개·이미지 | 연동 | `profiles`와 `avatars`; 본인 행만 수정 |
| 앱에서 사진 게시 | 연동 | private `photos` Storage와 `photos`; 촬영일·저장 좌표 포함 |
| 본인 사진 설명·공개 여부·위치 정확도 수정 | 연동 | `photos` 본인 행 UPDATE; 공개 전환 시 `shared` 호환 필드도 함께 변경 |
| 앱에서 게시 사진 삭제 | 연동 | `photos` 본인 행과 `photos` Storage 객체를 함께 삭제 |
| 좋아요·취소 | 연동 | `set_photo_like` RPC와 `user_likes`; 서버 총수를 양쪽에서 재조회 |
| 댓글 작성·본인 댓글 삭제 | 연동 | `comments`; 같은 사진 상세에서 양쪽이 재조회 |
| 신고·차단·차단 해제 | 연동 | `content_reports`·`user_blocks`; 웹과 앱의 RLS 조회 범위에 함께 반영 |
| 계정 삭제 | 연동 | 운영 `delete-account` 함수가 Auth·프로필·게시 사진·반응·Storage를 함께 정리 |
| 의견 보내기 | 서버 저장 | `product_feedback`에 저장되며 일반 사용자에게 다시 노출하지 않음 |
| 웹 앨범 | 부분 연동 | 앱은 같은 `albums`·`album_photos`를 읽기만 하며 편집은 웹 전용 |
| 기기 내 사진 목록·원본·로컬 위치 | 로컬 전용 | MediaLibrary와 백업 제외 SQLite; 게시 확정 전에는 서버 전송 없음 |
| 앱 설정 기본값 | 로컬 전용 | 계정별 AsyncStorage; 웹 설정과 자동 동기화하지 않음 |
| 검색어·지도 시점 | 비저장 | 현재는 개인 활동 기록으로 서버에 저장하지 않음 |
| 랜딩 관리자 편집 | 웹 전용 | 앱은 공개된 `landing_sections` 결과만 읽음 |

## 이번 검수에서 수정한 불일치

1. 앱 게시가 촬영일과 위치를 버리고 업로드 시각·빈 좌표를 저장하던 문제를 수정했다.
2. 앱 사진 상세에 본인 사진의 설명, 공개 여부, 위치 정확도 수정과 서버 저장을 추가했다.
3. 게시 파일에서 EXIF 원문은 계속 제거하되 촬영일과 위치가 별도 서버 필드로 저장된다는 안내와 스토어 개인정보 원장을 맞췄다.

## 운영 DB 확인

- `photos`, `user_likes`, `comments`, `profiles` 모두 RLS가 활성화되어 있다.
- `photos` INSERT·UPDATE·DELETE는 `auth.uid() = owner_id`인 소유자만 허용한다.
- `user_likes`는 로그인한 본인 행만 읽기·추가·삭제할 수 있다.
- `comments`는 보이는 사진에만 작성할 수 있고 본인 댓글만 삭제할 수 있다.
- `set_photo_like`는 인증과 사진 가시성을 함수 안에서 검사한 뒤 좋아요 행과 총수를 한 트랜잭션으로 갱신한다.
- 사진 위치 트리거는 입력 좌표를 변경하지 않고 소유자 전용 위치 테이블에도 같은 값을 보존한다.

## 남은 실기기 관문

자동 테스트와 운영 DB 카탈로그 읽기만으로 실제 로그인 세션의 쓰기 왕복을 대신하지 않는다. 서명된 iPhone·Android 앱에서 테스트 계정으로 앱 게시 → 웹 확인 → 앱 수정 → 웹 확인 → 웹 좋아요 취소 → 앱 확인 순서를 마지막으로 수행해야 한다. 현재 사용자 데이터는 이 검수에서 변경하지 않았다.
