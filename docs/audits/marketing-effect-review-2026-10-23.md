# 이끼 마케팅 효과 확인 — 2026-10-23

## 현재 판단

**소셜에서 사이트로 들어온 방문은 확인되지만, 특정 쇼츠의 성과나 가입·활성화 증가까지 입증되지는 않았다.**
Cloudflare의 최근 7일에는 방문 62회, 그중 페이스북 3회·인스타그램 1회가 기록됐다.
직접 유입 53회는 출처를 특정할 수 없다. 운영·검수 방문도 분리되지 않아
62회를 모두 신규 고객이나 마케팅 성과로 해석하지 않는다.
실패 판정이 아니라, 소셜 유입 신호는 작게 관측됐고 전환 성과는 추가 근거가 필요한 상태다.

## 방문·유입 실측 (오후 추가 확인)

2026-10-23 오후 2:31 한국시간에 Cloudflare 로그인 복구를 확인하고 조회했다.
필터는 `Site = ikkyee.com`, `Exclude bots = Yes`, `Last 7 days`다.
달력에 표시된 범위는 **10/16 14:31~10/23 14:31 (GMT+9)**이며,
아래 값은 당시 대시보드 표시값이다. 방문 수는 정확한 고유 인원 수가 아니다.

| --- | ---: | ---: |
| 방문 | 62회 | 100% |
| 페이지뷰 | 62회 | — |

- 유입처 5개 항목의 합이 전체 62회와 일치했다. 해당 표에서 YouTube 경유로
  구분된 항목은 없었다. 출처가 전달되지 않는 방문까지 포함해 유튜브 유입이 0회라고 단정하지 않는다.
- 직접 유입에는 출처가 전달되지 않은 앱·메신저 등의 방문도 섞일 수 있다.
  특정 홍보 계정이나 게시물에서 발생한 클릭 수로 소셜 방문을 단정할 수도 없다.
- 국가 표시값은 한국 32회, 미국 23회, 아일랜드 3회, 중국 3회, 대만 1회였다.
  국가 값으로 고객 여부나 자동 방문 여부를 판정하지 않는다.
- 표시된 페이지 로드 시간은 1,589ms였다. 모바일은 방문 3회로 작아
  이 전체 값을 휴대전화 성능으로 일반화하지 않는다.
- 페이지뷰와 방문이 같아도 내부 화면 이동을 측정하지 않는 현재 설정에서는
  이탈률 100%나 '첫 화면만 보고 떠남'으로 해석할 수 없다.

### 기간·표본 관련 주의

- 첫 조회의 최근 24시간에는 방문·페이지뷰 각 15회, 직접 유입 13회·Google 2회,
  데스크톱 15회가 표시됐다. 운영·검수 방문을 제외하지 못했으므로 성장 근거로 사용하지 않는다.
- 가입 집계와 같은 완결 기간인 10/16 00:00~10/23 00:00도 조회했다.
  방문·페이지뷰 각 60회였으나 **Visits summary의 Info 툴팁에
  `Based on a 10% sample of page load events`가 표시**됐다.
  해당 보기를 정확한 60명의 실측이나 최근 7일 62회와의 단순 차이로 해석하지 않는다.
- 주 보고서의 `Last 7 days` 보기에는 이 표본 안내가 표시되지 않았다.
  표본 경고가 있는 과거 기간과 섞어 정확한 증감률·일별 증감을 계산하지 않았다.
- 가입 비교 기간은 자정 기준, 방문 주 보고서는 오후 2:31 기준으로 서로 다르다.
  이 두 집계로 방문→가입 전환율을 계산하지 않는다.

- 현재 공개사진은 생성 시각과 현재 공개 상태로 추정한다. 실제 공개 전환 시각이나 삭제된 행동까지 복원하는 지표가 아니다.

## 방문·채널 통계 확인 상태와 측정 범위

현재 사이트는 10/15에 GA4에서 Cloudflare Web Analytics로 전환했다.
오전에는 로그인 만료로 조회할 수 없었으나 오후에 재인증된 화면에서
방문·페이지뷰·유입처·기기·페이지 로드 시간의 표시값을 확인했다.
과거 설치 점검의 QA 수치를 이번 마케팅 성과로 재사용하지 않았다.

- 사이트 설정은 공개 페이지의 최초 진입만 측정한다(`spa: false`).
  해시 화면 이동, 로그인·사진 등록·앨범 생성은 전환 이벤트로 집계되지 않는다.
- 앱, 개발 미리보기, 일부 국가, 비공개 화면 직접 진입은 수집 범위에서 제외된다.
  따라서 Cloudflare 수치를 전체 실제 서비스 이용량으로 볼 수 없다.
- Cloudflare의 Visits는 외부 사이트 또는 직접 링크에서 시작한 방문 기준이다.
  정확한 순방문자 수로 표현하지 않는다.
- Cloudflare Web Analytics는 현재 UTM과 사용자 지정 이벤트를 지원하지 않는다.
  링크에 UTM만 붙여서는 현재 대시보드에 영상별 전환 보고서가 만들어지지 않는다.
- 광고 차단이나 유입 정보가 전달되지 않는 경우 측정·유입 분류가 누락될 수 있다.
  직접 유입을 모두 검색·유튜브 유입으로 간주하지 않는다.

사이트 근거: [수집 설정](../cloudflare-web-analytics.md), `js/analytics.mjs`,
`js/analytics-ui.mjs`, `functions/api/config.js`.
제품 정의는 [Cloudflare 지표 설명](https://developers.cloudflare.com/web-analytics/data-metrics/high-level-metrics/),
[UTM·이벤트·수집 한계 FAQ](https://developers.cloudflare.com/web-analytics/faq/)에서 10/23에 확인했다.

## 다음 판정을 위한 확인 순서

1. 현재 기준은 최근 7일 방문 62회, 확인된 소셜 유입 4회, 모바일 3회다.
   같은 기간·필터·표본 조건으로 다음 기간과 비교한다. 운영·검수 방문이 섞였다는 한계를 함께 남긴다.
2. 수집 전환일 이전과 이후를 섞어 증감률을 계산하지 않는다.
   완결 기간 비교는 동일 조건의 10/16~22와 10/23~29처럼 수집이 활성화된 두 기간으로 잡을 수 있지만,
   과거 기간의 표본 보정 안내를 확인하고 이를 무시한 정밀한 증감률을 만들지 않는다.
3. 실제 홍보 게시일, 채널, 게시물 조회수와 프로필·사이트 링크 클릭 수를 해당 플랫폼 자료와 대조한다.
   이번에는 채널 관리 화면의 조회·클릭 자료를 확보하지 않았으므로 전환율이나 광고 수익률을 계산하지 않는다.
4. 가입·첫 업로드 결과는 충분한 표본과 관찰 7일을 확보한 뒤 별도로 비교한다.
   방문 상승만으로 가입 효과나 마케팅 인과관계를 확정하지 않는다.

분석 요청에 따라 자료만 확인했다. 새 추적 SDK, 개인별 이벤트 저장, UTM 수집,
광고 계정 설정이나 예산 변경은 이번 작업에 추가하지 않았다.
