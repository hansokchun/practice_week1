# 이끼 마케팅 효과 확인 — 2026-10-23

## 현재 판단

현재 확보한 실측으로는 최근 마케팅이 가입·활성화를 늘렸다고 판단하기 어렵다.
실패 판정이 아니라 **판정할 표본과 유입 자료가 충분하지 않은 상태**다.
아래 가입 집계는 실제 Supabase 조회 결과이고, 방문·채널 유입 수치는 아직 확보하지 못했다.

- 첫 업로드·첫 앨범·공개사진·타인 공개사진 좋아요는 가입 후 7일 기준이다.

  최신 포함 가능 가입 주차는 UTC 10/5~10/11이다.
- 반환된 완결 가입 코호트도 모두 최소 표본에 못 미쳐 가입 수와 모든 활성화 수치·비율이 숨김 처리됐다.
- 숨김은 0명 또는 전환 실패를 뜻하지 않는다. 운영자·테스트 계정을 분리한 신규 고객 수라고도 볼 수 없다.
- 현재 공개사진은 생성 시각과 현재 공개 상태로 추정한다. 실제 공개 전환 시각이나 삭제된 행동까지 복원하는 지표가 아니다.

기준: [Public Beta Metrics](../product/public-beta-metrics-2026-07-26.md).

## 방문·채널 통계 확인 상태와 측정 범위

현재 사이트는 10/15에 GA4에서 Cloudflare Web Analytics로 전환했다.
Cloudflare 통계 화면은 로그인 만료로 재인증이 필요하다. 이번 확인에서는
Visits·Page views·Referer hosts·기기·실사용 성능 수치를 읽지 못했으며 추정치를 넣지 않았다.
과거 설치 점검에서 기록한 QA 방문도 이번 마케팅 성과로 재사용하지 않았다.

- 사이트 설정은 공개 페이지의 최초 진입만 측정한다(`spa: false`).
  해시 화면 이동, 로그인·사진 등록·앨범 생성은 전환 이벤트로 집계되지 않는다.
- 앱, 개발 미리보기, 일부 국가, 비공개 화면 직접 진입은 수집 범위에서 제외된다.
  따라서 Cloudflare 수치를 전체 실제 서비스 이용량으로 볼 수 없다.
- Cloudflare의 Visits는 외부 사이트 또는 직접 링크에서 시작한 방문 기준이다.
  정확한 순방문자 수로 표현하지 않는다.
- Cloudflare Web Analytics는 현재 UTM과 사용자 지정 이벤트를 지원하지 않는다.
  링크에 UTM만 붙여서는 현재 대시보드에 영상별 전환 보고서가 만들어지지 않는다.
- 광고 차단이나 유입 정보가 전달되지 않는 경우 측정·유입 분류가 누락될 수 있다.
  직접 유입을 모두 검색·유튜브 유입으로 간주하지 않는다.

사이트 근거: [수집 설정](../cloudflare-web-analytics.md), `js/analytics.mjs`,
`js/analytics-ui.mjs`, `functions/api/config.js`.
제품 정의는 [Cloudflare 지표 설명](https://developers.cloudflare.com/web-analytics/data-metrics/high-level-metrics/),
[UTM·이벤트·수집 한계 FAQ](https://developers.cloudflare.com/web-analytics/faq/)에서 10/23에 확인했다.

## 다음 판정을 위한 확인 순서

1. Cloudflare에 로그인한 뒤 봇 제외 조건에서 최근 완결 7일의 방문·유입 도메인·모바일 비중을 확인한다.
2. 수집 전환일 이전과 이후를 섞어 증감률을 계산하지 않는다.
   첫 완결 비교는 동일 조건의 10/16~22와 10/23~29처럼 수집이 활성화된 두 기간으로 잡을 수 있다.
3. 실제 홍보 게시일, 채널, 게시물 조회수와 링크 클릭 수를 해당 플랫폼 자료와 대조한다.
   이번에는 채널 관리 화면의 조회·클릭 자료를 확보하지 않았으므로 전환율이나 광고 수익률을 계산하지 않는다.
4. 가입·첫 업로드 결과는 충분한 표본과 관찰 7일을 확보한 뒤 별도로 비교한다.
   방문 상승만으로 가입 효과나 마케팅 인과관계를 확정하지 않는다.

분석 요청에 따라 자료만 확인했다. 새 추적 SDK, 개인별 이벤트 저장, UTM 수집,
광고 계정 설정이나 예산 변경은 이번 작업에 추가하지 않았다.
